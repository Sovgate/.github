# Security policy

Sovgate handles payments, so we take security reports seriously. Thank you for helping keep Sovgate and the businesses that use it safe.

## Reporting a vulnerability

Email **[security@sovgate.com](mailto:security@sovgate.com)** with enough detail for us to reproduce the issue.

Please don't open a public issue, discussion or pull request for a security problem.

If you can, include:

- The product, repository and version affected
- The steps to reproduce the issue
- The impact you think it has
- A proof of concept

**Never include real card numbers, live API keys or other people's personal data.** Use test mode and test data only.

## Testing rules

When you look for or test a weakness:

- Test only against your own Sovgate account, in test mode.
- Don't access, change or keep data that isn't yours.
- Don't disrupt Sovgate's services or run denial-of-service tests.
- Don't use social engineering or physical attacks.

Please give us reasonable time to fix an issue before you share details publicly.

## What to expect

We'll acknowledge your report as soon as we reasonably can, keep you updated while we investigate, and tell you when the issue is fixed.

## Scope

In scope:

- The libraries and the API specification in the Sovgate GitHub organization
- The Sovgate API and Dashboard

Out of scope:

- Services run by third parties that we don't control

## Supported versions

Our libraries are in development and not yet released. Once they are, we'll fix security issues in the latest version of each.

We don't currently run a paid bug bounty program.
